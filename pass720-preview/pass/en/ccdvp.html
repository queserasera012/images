Production integration, reliability and grounding (20%, top priority)

Separate errors by kind (“retry everything” and “fall back on everything” are wrong)

What happenedRight handling
429 rate limitExponential backoff plus jitter · retry-after
529 overloadedBackoff · another path / fallback
Safety refusalDo not go around it. Safe fallback · a person
Cut off at max_tokensContinue generation · revisit the limit
invalid_request (400)Fix it and send (a retry gives the same)
pause_turnSend the content back as is and continue

Which constraint are you hitting

429 rate · remaining limit= rate limit
Tokens per minute= throughput
Completion time and unit price= batch economics

Diagnose RAG stage by stage (from the front)

IngestionAre the chunks cut badly
→
RetrievalRecall: is the right document among the candidates
→
RerankingPrecision: does it come out on top
→
GenerationDoes it use the grounds · citations

Points not to drop

  • Proper nouns, model numbers and IDs are missed → hybrid search plus metadata (vectors alone are weak)
  • Fixing the prompt when the right document is not among the candidates is wrong (do not fix a retrieval problem in generation)
  • To have it show its grounds → citations. Design so that claims that cannot be cited are not made
  • Caching: prefix match. The breakpoint goes at the end of the stable part. Rising cache_read_input_tokens means it works. cache_creation_input_tokens every time = a changing value in the prefix. Changes go after the boundary
  • For tool definitions, cache_control on the last tool caches the whole set. Changing one invalidates all of it. Below the minimum length it fails to cache with no error
  • Even with the shape guaranteed by structured output, validating the meaning is yours to do

Evaluation engineering (12%)

Four biases of the judge (LLM grading)

VerbosityScores long answers higher → criteria that do not score length
PositionPicks whichever came first → score twice with the order swapped
Self-preferenceFavors its own family → a model from a different family
DriftThe standard moves when the judge version changes → recalibrate

Graders and AI review alike: authority only after comparison with people

ShadowRun alongside with no authority
→
CalibrationAgreement with people · false-positive rate
→
Limited gateBlock on critical findings only
→
Expansion

Points not to drop

  • Regression by eval for settings changes too: run it when CLAUDE.md, a Skill, a tool description, the model or effort changes
  • The trap of “a good enough number”: even at 93% accuracy, are the failures clustered in one kind? Read 71% agreement net of agreement by chance
  • Grade from the cheapest up: code (deterministic) → LLM judge → people
  • Feed production failures back into the eval set

Cost and latency (8%)

SymptomMove
TTFT short, total longStreaming (perceived speed) · shorter output
TTFT long, input largeCaching
Slow from calling tools in turnRun in parallel, results in one message
Long reasoning on a simple taskLower effort (confirm quality by eval)
Input tokens swell from resent tool resultsProgrammatic tool calling (only the output reaches Claude)
Too many tools, heavy definitionsTool search · load only what is needed
Work stops partwayRaise effort one level → the model if that fails
Large jobs with no hurryBatches (50% off)
Effort is “how hard it tries”; the model is “what it knows”. Short on knowledge or ability: the model. Too little or too much work: effort. After changing the model, start effort again from the default. The order to apply: caching first → then programmatic tool calling.

Operating agent fleets (10%)

Fixing everything and freeing everything are both wrong

Who decidesWhat
Central (the floor)The permission floor · hooks on dangerous commands · the MCP allowlist · telemetry (managed settings)
Teams (the ideas)CLAUDE.md · Skills · slash commands

Points not to drop

  • The three-piece set for unattended operation: checkpoints, notification, escalation. Landing on main takes human approval
  • AI findings neither approve nor block (at first). Require approval by a human code owner
  • Trust the result of an unattended run only after reading the diff, a test hook, and a re-review in a fresh context
  • A pipeline stops waiting for confirmation → dontAsk and an allowlist
