統合（19%・最重点）

つなぎ方選ぶ場面
API のツール利用1 つの製品の中だけで使うツール（MCP を既定にしない）
MCP複数のクライアント・チームで同じ連携を共有
エージェント間組織をまたぐ
一括で渡すツール・文書が少なく固定
段階的ディスカバリー多い・更新される・一部しか要らない
実行基盤向く場面
Messages API の自前ループ完全な制御が要る。運用は全部自分
自前ホストの Agent SDK／ヘッドレス Claude Codeループは任せ、実行環境とデータは自分の管理下
Claude Managed Agents運用負担を小さく・長時間や再開。データは Anthropic 側（データ所在の制約があると不可）

RAG の形（集計の質問は SQL。RAG ではない）

取り込み構造に沿ったチャンク＋オーバーラップ
→
検索ハイブリッド（ベクトル＋キーワード）
→
再ランク適合率を上げる
→
フィルタメタデータで権限・テナント分離
→
生成引用つき

落とさないポイント

  • 最小権限：使わないツールは外す（ログや確認を足すより先）
  • 認可はツール実行時に、呼び出し元ユーザーの権限で。利用者の役割はサーバー側で注入（申告を信用しない）
  • 副作用のある行動 → 実行前の決定的な認可。出力フィルタでは守れない
  • 冪等性キーで二重実行（再試行による二重返金）を防ぐ
  • 個人情報は必要な項目だけ・参照 ID で渡す。ZDR・テナント分離は設計の最初に

開発者の生産性と運用支援（7%）

最低限

  • 展開は推進役から少人数ずつ。全員一斉は不正解
  • 運用の問題は手順書に残してチームに教える（自分で直して終わりにしない）
  • 組織の下限は管理設定（最優先・上書き不可）、チームの工夫は CLAUDE.md・Skill・プラグイン
  • 権限モード：無人は dontAsk＋許可リスト。bypassPermissions は隔離環境だけ
